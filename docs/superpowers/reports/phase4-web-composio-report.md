# Phase 4 — apps/web Composio integrations UI

Status: **DONE**

## Summary

Added a per-user "Integrations" section to `apps/web` (accounts list + detail page), a sidebar
nav entry, and re-wired the agent wizard's Tools step to let a user attach one of their own
Composio accounts. Backend (`orpc.composio.*`, already user-scoped) was not touched.

## Files created

Recovered from git history (`11b772b~1`) and adapted to `apps/web` conventions (web's
`@/utils/orpc`, `@/utils/api-types`, web's `DeleteConfirm`/`ListToolbar`/`Pagination`/
`useListView` list primitives, web's toast wording, `/integrations` route names instead of
`/composio`):

- `apps/web/src/components/integrations/add-account-dialog.tsx` — ported as-is from
  `apps/admin/src/components/composio/add-account-dialog.tsx`, plus a success toast on create
  (admin's version had none).
- `apps/web/src/components/integrations/connections-section.tsx` — ported from
  `connections-section.tsx`, plus a success toast on disconnect.
- `apps/web/src/components/integrations/toolkits-section.tsx` — ported 1:1 from
  `toolkits-section.tsx` (search, connect → `window.open(redirectUrl, "_blank", "noopener,noreferrer")`).
- `apps/web/src/components/integrations/placeholder.ts` — ported 1:1 (`queryPlaceholder` helper
  used by both sections to surface query errors, e.g. a bad API key, in the empty-row text).
- `apps/web/src/components/agents/composio-accounts-field.tsx` — ported from
  `apps/admin/src/components/agents/composio-accounts-field.tsx` (single-select stored as a
  0-or-1-item array); added the required hint line with a `Link` to `/integrations` when the
  user has no accounts ("No integrations yet. **Add one in Integrations** to link tools.").

Written new for this task (no old equivalent, or reshaped for the web list-view house style):

- `apps/web/src/components/integrations/accounts-list.tsx` — replaces admin's bare
  `accounts-table.tsx`. Uses the same `ListToolbar` + `useListView` + `Pagination` pattern as
  `agents-card.tsx` (search by name, paginated table), shows `AccountsSkeleton` while loading,
  and shows `IntegrationsEmptyState` (with an inline `AddAccountDialog` as the CTA) when the
  user has zero accounts — instead of admin's plain "No composio accounts yet." table row.
- `apps/web/src/components/integrations/account-detail.tsx` — new wrapper for the detail route:
  resolves the account's name from `listAccounts` (composio has no `getAccount` endpoint) to
  render a page heading, shows `AccountDetailSkeleton` while that query is pending, a "not
  found" message if the id doesn't match one of the user's accounts, then renders
  `ConnectionsSection` + `ToolkitsSection` (admin's detail route rendered those two directly
  with no heading/skeleton).
- `apps/web/src/components/integrations/integrations-skeleton.tsx` — `AccountsSkeleton` (mirrors
  `agents-skeleton.tsx`'s row shape: toolbar + divided rows) and `AccountDetailSkeleton`
  (mirrors two bordered row-list sections). Admin had no loading skeletons at all (used inline
  "Loading…" table-cell text via `queryPlaceholder`, which the sections still do for
  revalidation — the route-level skeletons only cover first paint).
- `apps/web/src/components/integrations/empty-state.tsx` — `IntegrationsEmptyState`, styled like
  `apps/web/src/components/dashboard/empty-state.tsx` (icon + title + description + action slot).
- `apps/web/src/routes/integrations.index.tsx`, `apps/web/src/routes/integrations.$accountId.tsx`
  — thin route components, same shape as `agents.index.tsx` / admin's old composio routes.
